# 第一阶段设备端验收与交付

本记录对应设备接入、文件上传确认、语音下发与播放三个协议。测试后端为本地 Demo；故障分支由仅在测试机运行的临时后端模拟，未改动正式服务。

## 已在真实头盔验证

| 场景 | 结果 |
| --- | --- |
| 命令与语音 WebSocket 建立，`hello/hello_ack` 接受 | 通过；两条通道在线 |
| 主动断开 WebSocket 后重新连接 | 通过；约 11 秒后双通道恢复 |
| 实体拍照键、JPEG 上传、`upload_jpeg`、`accepted` | 通过；听到受理提示与分析语音 |
| 实体录音键、PCM 上传、`upload_pcm`、`accepted` | 通过；听到受理提示与回复 |
| HTTP 上传返回 503 | 通过；未发送文件通知，播放“网络异常，请重新操作” |
| `rejected + INVALID_FILE`（JPEG） | 通过；播放“处理失败，请重新拍照” |
| 文件通知后 5 秒未收到 `ack` | 通过；播放“服务无响应，请重新操作” |
| `rejected + SERVICE_BUSY` 与未知错误码 | 设备收到对应错误码并调用本地播报；现场听感待确认 |
| PCM 流正常结束 | 通过；设备返回 `voice_status=completed` |
| 播放期间 `voice_cancel` | 通过；设备返回 `voice_status=cancelled` |
| 重复取消、错误格式、字节数不完整、并发语音 | 通过；分别返回 `cancelled`、`UNSUPPORTED_FORMAT`、`INCOMPLETE_AUDIO`、`PLAYER_BUSY` |
| 取消或失败后再次播放 | 通过；下一段语音返回 `completed` |
| 同时开始第二段语音 | 通过；第二段返回 `PLAYER_BUSY`，原任务仍可取消 |

## 交付前尚需确认

- PCM 通知的 `rejected` 与 HTTP 上传 `4xx`、无响应、非法 JSON：代码按同一错误分支处理，尚未逐项在真实设备注入。
- `hello_ack` 拒绝、握手超时和 Ping/Pong：已实现接入控制与超时重连，尚未对每种拒绝码逐项模拟。
- 开机自启动、断电再上电、较长时间运行、Wi-Fi/4G 网络切换：临时测试程序已稳定运行，但新版尚未安装为开机程序。
- 音频播放的真实硬件错误 `PLAYBACK_ERROR`/`INTERNAL_ERROR`：无法仅靠正常软件指令稳定复现；部署后仍需观察。
- 现有工程师服务可以建立 WebSocket，但对新版 `hello` 返回旧式 `ack` 而非 `hello_ack`。因此它当前与新版设备接入协议不兼容；必须由后端工程师适配后再进行业务联调。

## 安装与回滚要点

当前真实设备开机时由 `/oem/helmet/helmet_monitor.sh` 启动 `/oem/helmet/helmet -c /oem/helmet/test.json`。测试时只在 `/tmp` 运行新版程序，原程序和配置均未覆盖。正式切换是更新设备应用与声音资源，并非刷写整套固件。

1. 先备份设备现有的可执行文件、配置、监控脚本和声音文件，并校验备份可读。
2. 使用本仓库源码交叉编译生成新 `helmet`；仓库 `install/oem/helmet/helmet` 是交接基线文件，不能直接当作新版产物部署。
3. 将新程序与 `install/oem/helmet/snd/upload_*.pcm` 一起部署。配置中的设备标识、HTTP 与 WebSocket 地址应在设备本地填写，不提交到 Git。
4. 启动后核对 `hello_ack`、实体按键上传、`ack`、语音播放和 10 秒重连。现有工程师服务尚未返回 `hello_ack`，在后端更新前，新版设备会反复尝试握手，不能完成业务对话。
5. 若启动或联调失败，停止监控脚本，恢复备份文件和配置，再启动原监控脚本。

交给后端工程师时，需同时提供三个协议的 ShowDoc 页面和设备应用版本/提交号。服务端先返回 `hello_ack`，否则设备不会发送业务文件通知。
